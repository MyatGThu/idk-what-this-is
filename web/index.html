Workflow

Four steps, no build tooling to learn.

  1. 01

    Write a markdown file

    Drop a new .md into prompts/. Front matter carries the title, summary and tags; a ```prompt block holds the text people copy.

  2. 02

    Commit it

    Prompt changes become diffs. Review them like code, blame them when a model regresses, revert them when a rewrite backfires.

  3. 03

    Push to the default branch

    A GitHub Actions job runs the index build and validates every file's front matter. Bad metadata fails the run instead of shipping quietly.

  4. 04

    Read it here

    Pages redeploys in about a minute. Each prompt gets a permalink you can paste into a ticket or a thread.

Built as a static site — no server, no database, no API keys.
